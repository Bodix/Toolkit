# Last version for Unity 2019.4

This commit is the last version of Toolkit and its packages developed in **Unity 2019.4.41f2**. From the next commit on, the minimum version is **Unity 2022.3.62f3**.

## How to come back

- **Tag:** `last-2019.4` — in Toolkit and in every package repository. It always points to this commit.
- **Branch:** `legacy/2019.4` — for urgent fixes only.
- **Unity:** 2019.4.41f2, changeset `6b23d448b533`.

Get this version into a separate folder, so your current working copy stays untouched:

```
git clone --recurse-submodules --branch last-2019.4 https://github.com/Bodix/Toolkit.git Toolkit-2019.4
```

Then open the `Toolkit-2019.4` folder in Unity 2019.4.41f2. If this Unity version is not installed, paste `unityhub://2019.4.41f2/6b23d448b533` into a browser to install it through Unity Hub.

To use one package in another Unity 2019.4 project: **Package Manager → + → Add package from git URL**, then the repository URL with `#last-2019.4` at the end, for example:

```
https://github.com/Bodix/Unity.Toolkit.Common.git#last-2019.4
```

Add dependencies first: Perfect Foundation before Perfect UI.

## Known problems

This version does not compile in the newest Unity:

| Unity | What breaks | Where |
|---|---|---|
| 6.5 and newer | The old `InstanceID` API (`GetInstanceID()` and others) became a compile error | NaughtyAttributes in Perfect Foundation, QHierarchy in Toolkit.Common, Evolunity |
| 6.6 and newer | `ILayoutElement` gained `maxWidth` and `maxHeight`, and `LayoutItem` does not have them | uLayout in Perfect UI |

Packages that depend on Perfect Foundation or Perfect UI break together with them.

The uLayout copy in Perfect UI also keeps the GUIDs of the original uLayout package. A project that has both gets GUID conflicts.

## Why we moved to Unity 2022.3

In short: the Asset Store no longer lets us reach Unity 2019.4 users, and keeping 2019.4 makes every update more expensive.

1. **The Asset Store accepts only Unity 2022.3 or newer.** Its validator rejects a lower `unity` value in `package.json`. So users of Unity 2019.4–2022.2 cannot install our packages from the store anyway: supporting 2019.4 costs time and reaches no one there.
2. **The Asset Store requires no obsolete-API warnings in the latest Unity.** Every new Unity release brings fixes. With 2019.4 as the minimum, each fix must also compile and be tested in 2019.4.
3. **Third-party code is written for Unity 6.** uLayout uses C# 9 and new Unity APIs, so every update had to be rewritten by hand for Unity 2019.4.
4. **Unity 2019.4 limits us to C# 7.3.** Unity 2022.3 has C# 9, the same as Unity 6.
5. **Unity 2019.4 is no longer supported.** Its public support ended in June 2022. Unity 2022.3 is the oldest version the Asset Store accepts.
6. **Assets must be made in the oldest supported version.** Prefabs and fonts saved in a newer Unity may not open in an older one. Keeping 2019.4 meant making every asset in 2019.4.
